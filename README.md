# 토끼의 낙서장

## 현재 구현과 실행

```sh
flutter pub get
flutter analyze
flutter test
flutter run
```

- Android와 iOS용 Flutter 프로젝트다. 홈, 첫 문제 준비, 60초 게임, 결과 복기를 구현했다.
- 홈의 토끼는 스케치북을 안고 가볍게 숨 쉬듯 움직인다. 기기의 동작 줄이기 설정을 존중한다.
- 카운트다운, 시작, 정답, 오답, 종료 효과음과 라운드 배경음악을 로컬 오디오 파일로 재생한다. 홈에서 음악과 효과음을 각각 끌 수 있으며, 앱이 백그라운드에 있으면 재생을 멈춘다.
- iPhone Duo에서 접힘 상태에 따라 레이아웃을 다시 계산한다. 접힌 화면은 옆 시스템 영역을 피하고, 펼친 화면에 충분한 폭이 생기면 그림판과 답안을 나란히 배치한다. 전환 중에도 현재 문제와 타이머는 이어진다.
- 현재 구현은 오프라인에서 345개 카테고리의 미리 저장된 획을 재생한다. 그림은 Google Quick, Draw! 샘플을 골라 한국어 라벨과 함께 재포장했다. 전체 그림과 보기의 사람이 하는 검수는 남아 있다. [데이터 출처](https://github.com/googlecreativelab/quickdraw-dataset) · [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)
- Android와 iOS 16 이상에서 첫 실행의 `스케치북 준비하기` 화면에서 약 126 MB의 SketchFlow 팩을 받거나 기본 그림으로 바로 시작할 수 있다. 기본 그림을 선택한 이후에는 앱을 다시 열면 홈으로 이동하고, 홈에서 AI 그림을 받을 수 있다. 일시정지하거나 앱을 다시 열어도 받은 부분부터 이어받는다. 설치된 팩은 다음 실행에서 자동으로 열리며 오프라인에서도 사용할 수 있다. 첫 두 문제는 저장된 그림으로 시작하고, 두 번째 문제를 푸는 동안 다음 AI 그림을 생성한다. 게임 화면에 각 그림의 출처를 표시한다.
- iOS는 등록된 AdMob 앱 ID를 사용한다. 홈과 결과는 Android와 iOS 모두 공식 테스트 배너 광고 단위를 요청한다. 출시 검토 시 실제 배너 광고 단위, 광고 동의 흐름과 스토어 개인정보 설정을 확인한다. 광고가 실패해도 오프라인에서 플레이할 수 있다. [AdMob Flutter 가이드](https://developers.google.com/admob/flutter/quick-start)

### SketchFlow 모델 팩

공식 체크포인트의 디코더를 ONNX로 옮기고, 제시어 345개의 텍스트 조건은 빌드 전에 계산한다. 앱은 받은 디코더로 256점의 획 좌표를 기기에서 새로 생성한다. 모델과 조건 파일은 다운로드가 끝난 뒤 SHA-256을 검증하고 캐시에 저장한다. OS가 캐시를 정리하면 홈에서 다시 받을 수 있다. [원본 모델과 MIT 라이선스](https://github.com/doudin404/SketchFlow)

공식 소스와 v1 체크포인트, 원본 추론 의존성 및 `onnx`, `onnxruntime`을 준비한 뒤 아래 명령을 실행한다. 배포 파일을 교체할 때는 `lib/sketchflow.dart`의 다운로드 주소와 해시도 갱신한다.

```sh
python tools/export_sketchflow.py path/to/SketchFlow path/to/sketchflow_v1.ckpt path/to/output
python tools/check_sketchflow.py path/to/output
```

### 첫 실행 모델 다운로드 화면

![토끼가 스케치북 상자를 여는 모델 다운로드 안내 및 진행 화면](<./토끼의 낙서장 첫 다운로드 시안.png>)

- **다운로드 전.** 첫 화면에서 **AI 그림 다운로드**를 기본 선택으로 안내한다. 모델 용량을 표시하고 음악과 효과음을 설정할 수 있다. 모델을 한 번 받으면 오프라인에서 새 그림을 생성한다. 연결할 수 없을 때는 **기본 그림으로 시작**으로 첫 판을 플레이하고, 이후 홈에서 AI 모델을 받을 수 있다.
- **다운로드 중.** 진행률과 **일시정지** 버튼을 표시한다. 일시정지 상태는 **이어받기**, 오류는 **다시 시도**로 구분한다. 중단 뒤에는 실제로 저장된 진행률을 표시한다.
- **다운로드 완료.** 다운로드 완료와 모델 확인을 구분해 표시한다. 모델이 준비되면 **AI 그림으로 시작** 버튼을 표시한다.

### 게임 시작 화면

![토끼가 스케치북을 펼치는 준비 화면과 연필이 첫 획을 그리는 플레이 화면](<./토끼의 낙서장 게임 시작 시안.png>)

시작을 누르면 토끼가 스케치북을 펼치고 **3 → 2 → 1 → 게임 시작!**이 표시된다. 숫자는 1초씩, 손글씨로 쓴 시작 문구는 0.45초 동안 잠깐 좌우로 흔들리며 보여준다. 이후 연필이 첫 획을 긋는 순간 60초 타이머와 손글씨 보기 네 개가 활성화된다. 복습 보기에도 같은 글꼴을 쓴다. 문제를 바꿀 때는 스케치북 링을 고정한 채 기존 종이를 위로 넘기고 새 그림이 드러난다. 기기의 동작 줄이기를 켜면 시작 문구가 멈춰 있고 종이는 즉시 바뀐다.

### 플레이 중 화면 상태

| 상태 | 화면 변화 |
|---|---|
| 오답 입력 | 짧은 진동과 함께 고른 보기만 흔들고, 붉은 배경과 ×를 표시한다. 첫 오답은 0.8초, 두 번째 오답은 그림 절반 전 2.6초와 절반 이후 1.5초 동안 보기가 잠긴다. 보기 위에 진행 막대를 표시한다. 2.6초 대기 때는 남은 시간과 그림을 더 보라는 안내를 표시한다. 잠금이 끝나면 남은 보기의 파란 테두리와 다시 답하라는 안내를 유지한다. 세 번째 오답에는 다음 그림 안내를 보여준다. |
| 건너뛰기 활성화 | 보기 아래 작은 둥근 버튼에 시간 차감을 표시한다. 잠겨 있을 때는 자물쇠를 표시하고, 그림 완성 2초 뒤에는 넘기기 아이콘과 함께 활성화한다. |
| 남은 시간 10초 이하 | 타이머 숫자를 강조하고 라운드당 한 번 연필 소리를 낸다. |
| 3연속 이상 정답 | 연속 정답 수가 3의 배수에 도달할 때 토끼와 연속 정답 수를 보여준다. |

### 공통 화면과 접근성

- 홈, 다운로드, 결과에서 둥근 손글씨 버튼과 종이 배경을 공통으로 사용한다. 광고 공간은 폭이 충분한 화면에서 미리 확보해 광고가 로드돼도 시작·다시 하기 버튼이 움직이지 않게 한다.
- 플레이 화면의 왼쪽에는 타이머, 오른쪽에는 점수를 둔다. AI 그림 여부는 가운데에 표시하고, 시간 차감과 보상은 그 아래에 잠깐 보여준다. 첫 문제에서 건너뛰기가 잠겨 있을 때는 활성화 시점을 안내한다.
- 화면 폭이 좁고 시스템 글자 크기가 크면 보기를 한 열로 배치한다. 동작 줄이기에서는 페이지 전환과 토끼 움직임을 줄인다.
- Android 에뮬레이터에서 모델이 없는 상태부터 다운로드, 오프라인 한 판, 결과와 복습까지 확인한다. 접힌 아이폰의 시스템 영역과 갤럭시 S24, 실제 첫 플레이 사용자가 안내 없이 진행할 수 있는지는 별도로 검증한다.

#### 95점 UX/UI 검수 절차

1. **오답 후 재선택.** 첫 오답과 그림 초반 두 번째 오답을 차례로 입력한다. 대기 안내가 끝난 뒤 누를 수 있는 보기를 확인한다. × 표시가 추가될 때도 각 보기의 위치는 유지한다.
2. **첫 실행과 다운로드.** 용량, 진행률, 일시정지와 이어받기, 오류 후 다시 시도, 모델 확인 완료 후 시작을 차례로 검수한다. 연결이 끊기면 실제 저장된 진행률을 확인하고 기본 그림 경로도 실행한다.
3. **게임 화면 배치.** 320px 폭, 시스템 글씨 2배, 좌우 안전 영역, 짧은 가로 화면을 검수한다. Android는 기기의 화면 회전 설정을 따른다. 짧은 가로 화면은 보기를 두 열로 배치해 그림 옆의 높이를 아낀다. 문구가 두 줄에도 들어가지 않으면 한 열로 배치한다.
4. **결과 화면.** 세로 화면은 점수와 놓친 그림을 위에서 차례로 보여주고, 짧은 가로 화면은 두 영역을 나란히 보여준다. 하단의 **한 판 더**와 **홈으로**는 같은 높이로 배치하고, 놓친 그림이 여러 개거나 글씨가 커도 하단 동작이 바로 보이는지 확인한다.
5. **첫 사용자.** 앱을 처음 보는 사람이 별도 설명 없이 다운로드 선택, 첫 답, 오답 뒤 재선택, 복습 또는 한 판 더를 찾는지 관찰한다. 아이폰과 갤럭시 S24에서 반복해서 멈춘 화면을 수정한 후 다시 확인한다.

## 한 판의 흐름

1. **시작**을 누르면 스케치북을 펼치고 카운트다운을 보여준다. 펜이 첫 획을 그리는 순간 60초 타이머가 시작된다.
2. 플레이어는 그림이 완성되기 전에도 보기 4개 중 하나를 고를 수 있다.
3. **정답**이면 1점을 얻고 다음 그림이 시작된다. 정답당 1초가 늘어나며 한 판의 보너스 합계는 최대 15초다. 오답을 누르면 고른 보기를 비활성화하고 추가 보기 입력을 잠근다.
4. **건너뛰기**는 그림이 완성된 지 2초 뒤부터 사용할 수 있다. 누르면 남은 시간이 3초 줄고 다음 문제가 나온다. 시간이 0초가 되면 즉시 라운드가 끝난다.
5. **시간이 끝나면** 맞힌 개수와 최고 기록, 놓친 그림을 보여준다. 놓친 그림을 누르면 제한 시간 없이 해당 문제를 다시 맞힐 수 있다. 복습 점수는 라운드 기록에 합산하지 않는다.

### 종료와 앱 복귀 규칙

- **세 번째 오답.** 해당 문제를 오답으로 기록하고 점수 없이 다음 문제로 넘어간다. 타이머는 계속 흐른다.
- **0초와 정답 입력.** 입력을 처리하는 시점에 시간이 남아 있으면 정답을 인정한다. 0초에 도달하면 보기를 잠그고 현재 점수로 결과를 표시한다.
- **앱이 백그라운드로 이동하거나 화면이 잠길 때.** 타이머는 계속 흐른다. 제한 시간 안에 돌아오면 경과 시간에 해당하는 획과 남은 시간을 표시한다. 시간이 끝났으면 결과 화면으로 이동한다.
- **문제 팩을 모두 소진할 때.** 같은 판의 문제는 반복하지 않는다. 마지막 문제를 풀거나 건너뛰었고 다음 문제가 없으면 결과를 표시한다.

## 그리는 연출

한 판의 경과 시간에 따라 펜 속도를 기본 속도에서 최대 2배까지 서서히 높인다. 같은 그림을 그리는 중에도 획이 자연스럽게 이어진다.

펜 끝이 움직이고 지나간 자리에 선이 남는다. 획이 끝나면 펜을 잠깐 들고 다음 위치로 옮긴다. 완성된 그림은 답을 고르거나 건너뛸 때까지 남는다.

우산의 손잡이가 먼저 나오면 낚싯바늘이나 지팡이처럼 보인다. 플레이어는 지금 답을 고를지, 다음 획을 기다릴지, 문제를 건너뛸지 결정한다.

## 레벨 디자인

한 판은 60초로 시작한다. **결정적인 획이 나오는 순서, 보기의 유사도, 제시어의 친숙함**으로 난이도를 조절한다. 같은 제시어도 획 순서와 보기를 바꾸면 다른 난이도의 문제가 된다.

| 단계 | 설계 원칙 | 우산 문제 예시 |
|---|---|---|
| 1 · 입문 | 대표 윤곽을 먼저 보여주고 모양이 서로 다른 보기를 제시한다. | 지붕과 손잡이를 초반에 그린다. 보기는 우산, 사과, 컵, 신발이다. |
| 2 · 쉬움 | 한두 획 더 보면 정답이 드러난다. | 반원을 먼저 그리고 곧바로 손잡이를 붙인다. 보기에 버섯이 섞인다. |
| 3 · 보통 | 초반에는 두 가지 답이 가능해 보인다. | 반원 아래에 살대를 하나씩 그려 우산과 버섯을 구분하게 한다. |
| 4 · 어려움 | 덜 특징적인 부분부터 그리고 비슷한 보기를 섞는다. | 구부러진 손잡이부터 그린다. 보기에 낚싯바늘과 지팡이가 있다. |
| 5 · 도전 | 마지막 몇 획에서 정답이 확실해진다. | 접힌 우산을 그린다. 끝에 천의 주름과 묶는 띠를 넣는다. |

### 한 판 안의 난이도 진행

| 현재 점수 | 다음 문제 난이도 |
|---|---|
| 0–1점 | 1단계 · 친숙한 제시어, 서로 다른 오답 3개 |
| 2–3점 | 2단계 · 친숙한 제시어, 비슷한 오답 1개 |
| 4–5점 | 3단계 · 전체 제시어, 비슷한 오답 2개 |
| 6–7점 | 4단계 · 전체 제시어, 의미가 가까운 오답 3개 |
| 8점 이상 | 5단계 · 전체 제시어, 실제 그림의 윤곽까지 가까운 오답 3개 |

두 문제 연속으로 풀지 못하거나 건너뛰면 다음 한 문제만 회복 문제로 출제한다. 난이도는 한 단계 낮고 최저는 1단계다. 보기 구성에는 OpenCLIP 영어 제시어 유사도와 직접 지정한 보기 조합을 쓰고, 컵과 머그컵처럼 구분이 어려운 조합은 함께 내지 않는다. 이상 좌표나 비정상적으로 긴 선, 짧은 조각이 과도하게 많은 AI 그림은 저장된 그림으로 바꾼다. 그림의 실제 식별성은 플레이테스트에서 확인한다.

#### 95점 레벨 디자인 검수 절차

1. **첫 정답을 확인한다.** 아이폰과 갤럭시 S24에서 앱을 처음 접하는 참여자에게 풀이 방법을 미리 설명하지 않고 일반 모드 한 판을 진행한다. 1차 목표는 참여자의 80%가 첫 두 문제 안에 정답을 맞히는 것이다. 첫 정답까지 걸린 시간과 해당 문제의 제시어·샘플 번호를 기록한다. 같은 그림에서 막히는 사례가 반복되면 초반 획에 특징이 더 잘 드러나는 샘플을 비교한다.
2. **5단계 진입을 비교한다.** 5단계까지 도달한 판에서 7점 동안 나온 일반 4단계 문제와 첫 5단계 문제의 건너뛰기 비율을 비교한다. 8점을 만드는 직전 한 문제는 항상 정답이므로, 그 한 문제 대신 7점 구간의 시도들을 기준으로 삼는다. 시간 종료는 별도로 집계한다. 첫 5단계의 건너뛰기가 15%p 이상 늘면 해당 그림에서 다른 보기가 합리적으로 보였는지 관찰하고 보기 하나 또는 그림을 교체한다.
3. **회복과 복귀를 연달아 확인한다.** 회복 문제의 정답률과, 이를 맞힌 뒤 일반 난이도로 돌아간 첫 문제의 정답률·건너뛰기 비율을 함께 본다. 다음 문제 전에 판이 끝난 경우는 복귀 표본에 포함하지 않는다. 회복은 되지만 복귀 직후 다시 막히는 사례가 반복되면 복귀 첫 문제의 보기 유사도를 낮춰 재검수한다.
4. **결과를 모아 다시 평가한다.** 앱 정보의 레벨 진행 검수에서 기기별 결과를 복사하고, 첫 참여자 한 명당 첫 판 한 건만 합산한다. 5단계에 도달할 수 있는 반복 플레이어의 기록은 진입과 회복 확인에 쓴다. 테스트 기록에는 기기, 빌드, 관찰한 행동, 교체한 그림 또는 보기를 남긴다. 샘플이 적을 때는 비율과 분모를 함께 해석한다. 제작 중 검증은 기록과 집계 동작을 확인하며, 95점 평가는 첫 사용자와 실기기 재검수에서 결정한다.

### 밸런스 확인

1·2단계에서 같은 제시어를 4번 이상 출제했고 정답률이 50% 미만이거나 건너뛰기 비율이 50% 이상이면 그 기기의 초반 후보에서 후순위로 돌린다. `python tools/rank_quiz_outlines.py`로 저장 그림의 윤곽 순위를 다시 만들 수 있다. `python tools/check_sketchflow.py path/to/output --outlines "garden hose" pear`로 고정 시드의 AI 그림과 획 데이터를 검수할 수 있다.

최근 20판의 경과 시간, 문제별 난이도와 출처, 정답·오답·건너뛰기, 첫 선택 시간, 난이도 완화 여부를 기기에 저장한다. 앱 정보의 난이도 비교에서 두 초반 문제, 승급, 회복 결과와 완성 후 반복 오답을 확인한다. 첫 두 문제에서 정답을 낸 판의 비율과 평균 첫 정답 시간도 표시한다. 같은 제시어와 단계에서 두 출처의 기록이 각각 6개 이상이고, 저장된 그림의 정답률이 65% 이상이면서 AI 그림보다 50%p 이상 높으면 해당 문제는 저장된 그림으로 출제한다. 정답 보너스 상한은 15초, 건너뛰기 차감은 3초다. 첫 오답 입력 잠금은 0.8초다. 두 번째 오답은 그림이 절반 나오기 전이면 2.6초, 그 이후에는 1.5초다.

같은 문제 순서에서 전략을 비교하려면 저장된 그림으로 실행하는 플레이테스트 빌드를 사용한다. 동일한 시드와 단계에서는 각 판의 제시어, 그림, 보기 순서가 재현된다. 기록은 일반 플레이와 별도로 저장된다.

```sh
flutter run --dart-define=QUIZ_PLAYTEST_SEED=42 --dart-define=QUIZ_PLAYTEST_LEVEL=5 --dart-define=QUIZ_PLAYTEST_RULES=early-retry --dart-define=QUIZ_PLAYTEST_STRATEGY=wait
```

같은 시드에서 빠른 추측, 결정적인 획을 기다리는 플레이, 모르겠으면 건너뛰는 플레이를 비교한다. 여러 시드와 서로 다른 숙련도의 플레이어를 사용해 점수, 라운드 길이, 첫 선택 시점, 건너뛰기 횟수를 기록한다. 일반 빌드에서는 1~5단계의 정답률과 첫 선택 시간, 난이도 완화 직후 정답률을 비교한다.

#### 95점 밸런스 디자인 검수 절차

같은 시드와 단계에서 각 전략과 비교 규칙을 배정한다. 같은 참여자에게 같은 시드를 반복 배정하지 않는다. 참가자가 맡은 전략을 `guess`, `wait`, `skip` 중 하나로 기록한다. 이 값은 기록을 분류하며 실제 선택은 참가자가 한다. 기존 규칙은 `baseline`, 조기 두 번째 오답 보정은 `early-retry`, 건너뛰기 −2초는 `skip-2`, 30초 이후 정답 +0.5초는 `late-bonus`다. 앱 정보의 **밸런스 검수**에서 규칙·전략별 기록을 복사한다.

| 순서 | 비교와 수정 기준 |
|---|---|
| 1 · 빠른 추측 | 점수, 오답 횟수, 그림 절반 전 첫 선택 비율, 라운드 길이를 비교한다. 빠른 추측이 여러 문제 순서에서 유리하면 그림 절반 전의 두 번째 오답 대기를 먼저 비교한다. |
| 2 · 건너뛰기 | 한 번 이상 건너뛴 판 중 건너뛰기로 바로 끝난 비율을 본다. 초보자가 자주 종료되면 −3초와 −2초를 비교하며, 수정 후 건너뛰기 전략의 점수와 라운드 길이도 확인한다. |
| 3 · 정답 보너스 | 보너스 상한 도달 시점, 이후 추가 정답 수, 전체 라운드 길이를 기록한다. 상한에 일찍 도달하면서 라운드가 길어지는 경우 후반 보너스를 비교한다. |
| 4 · 그림 출처 | 일반 모드에서 같은 제시어와 단계의 AI·저장 그림 정답률, 정답까지 걸린 시간, 건너뛰기를 출처별로 비교한다. 시작 두 문제와 회복 문제는 비교 대상에서 제외한다. 출처별 기록이 각각 6개 이상인 조합을 우선 검수한다. |

`dart tools/check_round_balance.dart`는 앱의 시간·획 진행 규칙으로 난이도별 200개 시드를 재현한다. 빠른 추측은 정답 위치를 무작위로 놓고, 기다리기는 획 65%에서 모든 정답을 안다고 가정한다. 건너뛰기는 정해진 일부 문제에서 정답을 모르고 건너뛴다고 가정한다.

| 비교 | 자동 시나리오 결과 |
|---|---|
| 빠른 추측 | 기존 5단계에서 추측 29.69점, 기다리기 24.00점이었다. 두 번째 오답에 2.2초를 일괄 적용하면 추측은 25.20점, 그림 절반 전에만 2.6초를 적용하면 22.98점이었다. 마지막 방식을 일반 빌드에 반영했다. |
| 건너뛰기 | −3초와 −2초를 적용했을 때 200판 중 건너뛰기로 바로 끝난 판은 1단계에서 63→59판, 5단계에서 43→28판이었다. |
| 정답 보너스 | 5단계 기다리기 모형에서 30초 이후 +0.5초를 적용하면 보너스 상한 도달이 50.77초에서 70.77초로 늦어졌다. 평균 라운드 길이는 두 경우 모두 75초였다. |

건너뛰기와 보너스 대안은 실제 참여자 결과를 보고 적용 여부를 결정한다.

실기기에서 비교할 때는 기기, 빌드, 시드, 전략, 적용 규칙을 남긴다. 여러 시드에서 같은 문제가 반복되는지 확인하고 한 번에 하나의 규칙을 조정한 뒤 다시 비교한다. 시뮬레이션 결과는 규칙의 극단 사례를 찾는 데 사용하며, 밸런스 디자인 95점 판단에는 실제 참여자 결과를 사용한다.

제시어 345개는 [레벨 검수표](docs/quiz-level-review.csv)에서 검토한다. 자동 계산한 초반·완성 윤곽 여유는 같은 제시어의 윤곽과 가장 가까운 다른 제시어 간 유사도의 차이이며, 양수가 클수록 윤곽으로 구분하기 쉽다는 가설이다. 각 제시어의 친숙도, 헷갈리는 보기와 구분할 획, 여러 번 생성한 AI 그림의 식별성은 사람이 기록한다.

## 첫 버전과 로컬 AI

### 첫 버전 문제 구성

첫 제품 버전은 SketchFlow가 학습한 Quick, Draw! 카테고리 345개 전체를 출제 대상으로 삼는다. 각 카테고리에 한국어 정답, 오답 보기 세 개, 제시어 벡터를 연결한다. 아래 12개는 보기와 획을 설계하는 예시다. 보기 순서는 문제마다 섞고, 획 순서와 결정적인 획은 난이도에 맞는 생성 결과를 고르는 기준으로 삼는다.

| 정답 | 오답 보기 3개 | 획 순서 | 결정적인 획 |
|---|---|---|---|
| 우산 | 버섯, 낚싯바늘, 지팡이 | 손잡이 → 반원 → 지붕 가장자리 → 우산살 | 지붕 가장자리와 우산살 |
| 문어 | 오징어, 해파리, 거미 | 둥근 머리 → 눈 → 굽은 다리 → 빨판 | 굽은 다리 안쪽의 빨판 |
| 자전거 | 오토바이, 유모차, 킥보드 | 안장 → 삼각 차체 → 바퀴 → 페달 | 차체 가운데의 페달 |
| 고양이 | 토끼, 개, 여우 | 얼굴 윤곽 → 삼각 귀 → 코 → 양쪽 수염 | 짧은 주둥이 양옆의 수염 |
| 칫솔 | 빗, 붓, 포크 | 손잡이 → 좁은 목 → 작은 머리 → 칫솔모 | 작은 머리에 모인 짧은 칫솔모 |

| 소방차 | 버스, 구급차, 트럭 | 차체 → 바퀴 → 운전석 → 지붕 사다리 | 지붕 위에 놓인 사다리 |

### 구현 범위

- **첫 제품 버전.** iOS와 Android에서 한국어 제시어 345개, 60초 모드, 4지선다, 5단계 난이도와 점수별 진행, 최고 기록, 오답 및 건너뛰기 복기를 제공한다.
- **기기 내 생성.** 345개 제시어의 벡터를 미리 담고, 공통 SketchFlow 생성 모델은 최초 한 번 내려받는다. 이후 인터넷 연결 없이 각 제시어의 새 획을 만든다. 첫 두 문제는 초반 특징을 검수한 저장 그림으로 출제하고, 두 번째 문제를 푸는 동안 이후 문제의 AI 그림을 미리 생성한다. [SketchFlow 모델 카드](https://github.com/doudin404/SketchFlow/blob/main/MODEL_CARD.md)
- **출시 전 검증.** 갤럭시 S24와 지원할 아이폰에서 모델 다운로드 용량, 메모리 사용량, 그림 생성 시간, 완성 그림 정답률을 확인한다. 새 문제가 준비되는 속도와 생성된 획의 난이도 분류가 실제 60초 라운드에서 안정적으로 작동하는지 검증한다.

## 플레이테스트 기준

### 95점 재미 검수 절차

1. **일찍 맞히는 순간을 살린다.** 그림이 15% 이상 나오고 절반에 이르기 전 첫 선택으로 맞히면 짧은 효과음과 **빠른 정답!** 안내를 보여준다. 점수와 시간 보너스는 일반 정답과 같다. 효과음 설정을 따르고 오답 안내와 연속 정답이 먼저 표시된다.
2. **재도전할 이유를 보여준다.** 판을 끝내면 남은 최고 기록 차이 또는 다음 목표를 한 줄로 표시한다. 목표는 이번 판 점수와 시작할 때의 기록에서 계산한다.
3. **오늘의 낙서를 한 판 검수한다.** 기기의 날짜를 기준으로 한 30초 도전이다. 같은 날짜에는 저장된 그림과 문제 순서가 같고, 푼 문제 순번에 따라 난이도가 오른다. 오프라인에서 플레이할 수 있다. 도전 기록은 일반 모드 최고 기록과 밸런스 통계에서 분리한다.
4. **자발적인 재도전을 확인한다.** 첫 판을 끝낸 뒤 **한 판 더**로 두 번째와 세 번째를 시작하는 횟수를 기기에 기록한다. 앱 정보에서 빠른 정답과 일반 모드 재도전 기록을 확인하고, 새 기능이 실제로 다음 판을 시작하게 만드는지 실기기와 참여자 관찰로 판단한다.

- **오답 후 재선택을 알아차리는가.** 처음 플레이하는 사람에게 오답 안내를 미리 설명하지 않는다. 첫 오답 뒤 다시 누를 수 있는 보기를 스스로 찾는지, 잠긴 보기를 반복해서 누르거나 건너뛰기로 빠지는지 관찰한다.
  - 2026-11-25 확인. 안내를 보기 아래에 두고 재선택 가능한 보기를 강조한 버전에서 한 참여자가 첫 오답 뒤 멈추거나 다른 버튼을 눌렀다. 안내를 보기 위로 옮기고 건너뛰기 강조를 줄인 뒤, 같은 참여자가 다른 보기를 더 쉽게 눌렀다. 수정본을 처음 보는 참여자의 반응은 아직 확인하지 않았다.
- **몇 번째 획에서 맞히는가.** 입문 문제는 초반에, 도전 문제는 후반에 정답이 나오는지 확인한다.
- **찍기가 유리한가.** 획을 기다리는 플레이보다 보기를 빠르게 찍는 플레이가 높은 점수를 얻으면 오답 대기 시간을 조정한다. 오답별 입력 잠금과 그림 완성 후 2초 건너뛰기 대기 시간을 플레이테스트에서 확인한다.
- **왜 건너뛰는가.** 그림이나 보기의 모호함, 펜의 속도, 제시어의 친숙함을 살핀다.
- **60초가 끝나면 한 판 더 하는가.** 정답 직후 다음 그림으로 넘어가는 속도와 후반 난이도가 재도전을 끌어내는지 본다.
- **한 획 더 기다리는 게 재밌는가.** 같은 문제 팩으로 플레이하면서 답을 누르기 직전의 획, 오답 입력, 건너뛰기를 기록한다. 보기부터 연달아 누르는 편이 유리하면 오답 잠금을, 그림을 기다리는 시간이 길게 느껴지면 펜 속도를 조정한다.
