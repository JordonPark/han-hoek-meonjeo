# 토끼의 낙서장

## 현재 구현과 실행

```sh
flutter pub get
flutter analyze
flutter test
flutter run
```

- Android와 iOS용 Flutter 프로젝트다. 홈, 첫 문제 준비, 60초 게임, 결과 복기를 구현했다.
- 홈의 토끼는 스케치북을 안고 가볍게 숨 쉬듯 움직인다. 기기의 동작 줄이기 설정을 존중한다.
- 카운트다운, 시작, 정답, 오답, 종료 효과음과 라운드 배경음악을 로컬 오디오 파일로 재생한다. 홈에서 음악과 효과음을 각각 끌 수 있으며, 앱이 백그라운드에 있으면 재생을 멈춘다.
- iPhone Duo에서 접힘 상태에 따라 레이아웃을 다시 계산한다. 접힌 화면은 옆 시스템 영역을 피하고, 펼친 화면에 충분한 폭이 생기면 그림판과 답안을 나란히 배치한다. 전환 중에도 현재 문제와 타이머는 이어진다.
- 현재 구현은 오프라인에서 345개 카테고리의 미리 저장된 획을 재생한다. 그림은 Google Quick, Draw! 샘플을 골라 한국어 라벨과 함께 재포장했다. 전체 그림과 보기의 사람이 하는 검수는 남아 있다. [데이터 출처](https://github.com/googlecreativelab/quickdraw-dataset) · [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)
- Android와 iOS 16 이상에서 첫 실행의 `스케치북 준비하기` 화면에서 약 126 MB의 SketchFlow 팩을 받거나 기본 그림으로 바로 시작할 수 있다. 기본 그림을 선택한 이후에는 앱을 다시 열면 홈으로 이동하고, 홈에서 AI 그림을 받을 수 있다. 일시정지하거나 앱을 다시 열어도 받은 부분부터 이어받는다. 설치된 팩은 다음 실행에서 자동으로 열리며 오프라인에서도 사용할 수 있다. 첫 AI 그림은 카운트다운 전에 최대 6초 동안 준비한다. 생성이 늦거나 실패하면 저장된 그림으로 시작하며, 다음 그림은 플레이 중에 미리 생성한다. 게임 화면에 각 그림의 출처를 표시한다.
- iOS는 등록된 AdMob 앱 ID를 사용한다. 홈과 결과는 Android와 iOS 모두 공식 테스트 배너 광고 단위를 요청한다. 출시 검토 시 실제 배너 광고 단위, 광고 동의 흐름과 스토어 개인정보 설정을 확인한다. 광고가 실패해도 오프라인에서 플레이할 수 있다. [AdMob Flutter 가이드](https://developers.google.com/admob/flutter/quick-start)

### SketchFlow 모델 팩

공식 체크포인트의 디코더를 ONNX로 옮기고, 제시어 345개의 텍스트 조건은 빌드 전에 계산한다. 앱은 받은 디코더로 256점의 획 좌표를 기기에서 새로 생성한다. 모델과 조건 파일은 다운로드가 끝난 뒤 SHA-256을 검증하고 캐시에 저장한다. OS가 캐시를 정리하면 홈에서 다시 받을 수 있다. [원본 모델과 MIT 라이선스](https://github.com/doudin404/SketchFlow)

공식 소스와 v1 체크포인트, 원본 추론 의존성 및 `onnx`, `onnxruntime`을 준비한 뒤 아래 명령을 실행한다. 배포 파일을 교체할 때는 `lib/sketchflow.dart`의 다운로드 주소와 해시도 갱신한다.

```sh
python tools/export_sketchflow.py path/to/SketchFlow path/to/sketchflow_v1.ckpt path/to/output
python tools/check_sketchflow.py path/to/output
```

### 게임 시작 화면

![토끼가 스케치북을 펼치는 준비 화면과 연필이 첫 획을 그리는 플레이 화면](<./토끼의 낙서장 게임 시작 시안.png>)

시작을 누르면 토끼가 스케치북을 펼치고 **3 → 2 → 1 → 게임 시작!**이 표시된다. 숫자는 1초씩, 손글씨로 쓴 시작 문구는 0.45초 동안 잠깐 좌우로 흔들리며 보여준다. 이후 연필이 첫 획을 긋는 순간 60초 타이머와 손글씨 보기 네 개가 활성화된다. 복습 보기에도 같은 글꼴을 쓴다. 문제를 바꿀 때는 스케치북 링을 고정한 채 기존 종이를 위로 넘기고 새 그림이 드러난다. 기기의 동작 줄이기를 켜면 시작 문구가 멈춰 있고 종이는 즉시 바뀐다.

### 플레이 중 화면 상태

| 상태 | 화면 변화 |
|---|---|
| 오답 입력 | 짧은 진동과 함께 고른 보기만 흔들고, 붉은 배경과 ×를 표시한다. 첫 오답은 0.8초, 같은 문제의 두 번째 오답은 1.5초 동안 보기가 잠긴다. 보기 바로 위에서 잠금과 재선택을 안내하며, 보기 위치는 그대로 유지한다. 잠금이 풀리면 고를 수 있는 보기의 파란 테두리와 안내를 다음 입력까지 유지하고, 건너뛰기는 종이색으로 표시한다. 세 번째 오답에는 다음 그림 안내를 보여준다. |
| 건너뛰기 활성화 | 보기 아래 작은 둥근 버튼에 시간 차감을 표시한다. 잠겨 있을 때는 자물쇠를 표시하고, 그림 완성 2초 뒤에는 넘기기 아이콘과 함께 활성화한다. |
| 남은 시간 10초 이하 | 타이머 숫자를 강조하고 라운드당 한 번 연필 소리를 낸다. |
| 3연속 이상 정답 | 연속 정답 수가 3의 배수에 도달할 때 토끼와 연속 정답 수를 보여준다. |

### 공통 화면과 접근성

- 홈, 다운로드, 결과에서 둥근 손글씨 버튼과 종이 배경을 공통으로 사용한다. 광고 공간은 폭이 충분한 화면에서 미리 확보해 광고가 로드돼도 시작·다시 하기 버튼이 움직이지 않게 한다.
- 플레이 화면의 왼쪽에는 타이머, 오른쪽에는 점수를 둔다. AI 그림 여부는 가운데에 표시하고, 시간 차감과 보상은 그 아래에 잠깐 보여준다. 첫 문제에서 건너뛰기가 잠겨 있을 때는 활성화 시점을 안내한다.
- 화면 폭이 좁고 시스템 글자 크기가 크면 보기를 한 열로 배치한다. 동작 줄이기에서는 페이지 전환과 토끼 움직임을 줄인다.
- Android 에뮬레이터에서 모델이 없는 상태부터 다운로드, 오프라인 한 판, 결과와 복습까지 확인한다. 접힌 아이폰의 시스템 영역과 갤럭시 S24, 실제 첫 플레이 사용자가 안내 없이 진행할 수 있는지는 별도로 검증한다.

## 한 판의 흐름

1. **시작**을 누르면 스케치북을 펼치고 카운트다운을 보여준다. 펜이 첫 획을 그리는 순간 60초 타이머가 시작된다.
2. 플레이어는 그림이 완성되기 전에도 보기 4개 중 하나를 고를 수 있다.
3. **정답**이면 1점을 얻고 다음 그림이 시작된다. 정답당 1초가 늘어나며 한 판의 보너스 합계는 최대 15초다. 오답을 누르면 고른 보기를 비활성화하고 추가 보기 입력을 잠근다.
4. **건너뛰기**는 그림이 완성된 지 2초 뒤부터 사용할 수 있다. 누르면 남은 시간이 3초 줄고 다음 문제가 나온다. 시간이 0초가 되면 즉시 라운드가 끝난다.
5. **시간이 끝나면** 맞힌 개수와 최고 기록, 놓친 그림을 보여준다. 놓친 그림을 누르면 제한 시간 없이 해당 문제를 다시 맞힐 수 있다. 복습 점수는 라운드 기록에 합산하지 않는다.

### 종료와 앱 복귀 규칙

- **세 번째 오답.** 해당 문제를 오답으로 기록하고 점수 없이 다음 문제로 넘어간다. 타이머는 계속 흐른다.
- **0초와 정답 입력.** 입력을 처리하는 시점에 시간이 남아 있으면 정답을 인정한다. 0초에 도달하면 보기를 잠그고 현재 점수로 결과를 표시한다.
- **앱이 백그라운드로 이동하거나 화면이 잠길 때.** 타이머는 계속 흐른다. 제한 시간 안에 돌아오면 경과 시간에 해당하는 획과 남은 시간을 표시한다. 시간이 끝났으면 결과 화면으로 이동한다.
- **문제 팩을 모두 소진할 때.** 같은 판의 문제는 반복하지 않는다. 마지막 문제를 풀거나 건너뛰었고 다음 문제가 없으면 결과를 표시한다.

## 그리는 연출

한 판의 경과 시간에 따라 펜 속도를 기본 속도에서 최대 2배까지 서서히 높인다. 같은 그림을 그리는 중에도 획이 자연스럽게 이어진다.

펜 끝이 움직이고 지나간 자리에 선이 남는다. 획이 끝나면 펜을 잠깐 들고 다음 위치로 옮긴다. 완성된 그림은 답을 고르거나 건너뛸 때까지 남는다.

우산의 손잡이가 먼저 나오면 낚싯바늘이나 지팡이처럼 보인다. 플레이어는 지금 답을 고를지, 다음 획을 기다릴지, 문제를 건너뛸지 결정한다.

## 레벨 디자인

한 판은 60초로 시작한다. **결정적인 획이 나오는 순서, 보기의 유사도, 제시어의 친숙함**으로 난이도를 조절한다. 같은 제시어도 획 순서와 보기를 바꾸면 다른 난이도의 문제가 된다.

| 단계 | 설계 원칙 | 우산 문제 예시 |
|---|---|---|
| 1 · 입문 | 대표 윤곽을 먼저 보여주고 모양이 서로 다른 보기를 제시한다. | 지붕과 손잡이를 초반에 그린다. 보기는 우산, 사과, 컵, 신발이다. |
| 2 · 쉬움 | 한두 획 더 보면 정답이 드러난다. | 반원을 먼저 그리고 곧바로 손잡이를 붙인다. 보기에 버섯이 섞인다. |
| 3 · 보통 | 초반에는 두 가지 답이 가능해 보인다. | 반원 아래에 살대를 하나씩 그려 우산과 버섯을 구분하게 한다. |
| 4 · 어려움 | 덜 특징적인 부분부터 그리고 비슷한 보기를 섞는다. | 구부러진 손잡이부터 그린다. 보기에 낚싯바늘과 지팡이가 있다. |
| 5 · 도전 | 마지막 몇 획에서 정답이 확실해진다. | 접힌 우산을 그린다. 끝에 천의 주름과 묶는 띠를 넣는다. |

### 한 판 안의 난이도 진행

| 현재 점수 | 다음 문제 난이도 |

| 0–1점 | 1단계 · 친숙한 제시어, 서로 다른 오답 3개 |
| 2–3점 | 2단계 · 친숙한 제시어, 비슷한 오답 1개 |
| 4–5점 | 3단계 · 전체 제시어, 비슷한 오답 2개 |
| 6–7점 | 4단계 · 전체 제시어, 의미가 가까운 오답 3개 |
| 8점 이상 | 5단계 · 전체 제시어, 실제 그림의 윤곽까지 가까운 오답 3개 |

두 문제 연속으로 풀지 못하거나 건너뛰면 다음 한 문제만 한 단계 낮춘다. 가장 낮은 난이도는 1단계다. 보기 구성에는 OpenCLIP 영어 제시어 유사도와 직접 지정한 보기 조합을 쓰고, 컵과 머그컵처럼 구분이 어려운 조합은 함께 내지 않는다. 이상 좌표나 비정상적으로 긴 선, 짧은 조각이 과도하게 많은 AI 그림은 저장된 그림으로 바꾼다. 그림의 실제 식별성은 플레이테스트에서 확인한다.

### 레벨 디자인 수정 목록

| 수정 대상 | 검수 및 반영 기준 |
|---|---|
| 4·5단계의 차이 | 같은 제시어를 두 단계에서 비교한다. 4단계는 같은 종류의 보기, 5단계는 윤곽까지 비슷한 보기를 낸다. 완성 후 손잡이·바퀴처럼 정답을 가르는 특징을 검수표에 적고, 끝까지 두 답이 가능하면 보기를 교체한다. |
| 같은 단계의 AI 그림 편차 | 정답률이 낮거나 건너뛰기가 잦은 제시어를 우선한다. 같은 제시어를 여러 번 생성해 초반에 드러나는 특징과 완성 뒤 식별성을 각각 확인한다. 완성해도 알아보기 어려운 결과가 반복되면 검수한 보기 조합이나 저장된 그림으로 대체한다. |
| 승급·연속 실패 보정 | 첫 문제 정답률, 승급 전후 단계별 정답률과 첫 선택 시간, 난이도를 낮춘 직후 정답률을 본다. 특정 승급 구간에서만 정답률이 급락하면 우선 출제 조합을 조정한다. 연속 실패 보정 후에도 회복이 없거나 보정이 지나치게 자주 나오면 발동 조건을 조정한다. |

검수 대상은 최근 플레이 기록과 [345개 제시어 검수표](docs/quiz-level-review.csv)에서 고른다. 위 항목의 검수 결과와 반영한 문제를 기록한 뒤 레벨 디자인 점수를 다시 평가한다.

### 밸런스 확인

첫 문제는 초반 획을 알아보기 쉬운 제시어 후보에서 고른다. 저장된 그림으로 대체할 때는 해당 제시어의 초반 윤곽을 비교해 선정한 샘플을 쓴다. 5단계의 보기에는 저장된 그림의 간략한 윤곽을 비교한 순위를 사용한다. `python tools/rank_quiz_outlines.py`로 이 데이터를 다시 만들 수 있다.

최근 20판의 경과 시간, 문제별 난이도와 출처, 정답·오답·건너뛰기, 첫 선택 시간, 난이도 완화 여부를 기기에 저장한다. 앱 정보의 난이도 비교에서 AI 그림과 저장된 그림의 정답률과 풀이 시간을 확인할 수 있다. 같은 제시어와 단계에서 두 출처의 기록이 각각 6개 이상이고, 저장된 그림의 정답률이 65% 이상이면서 AI 그림보다 50%p 이상 높으면 해당 문제는 저장된 그림으로 출제한다. 정답 보너스 상한은 15초, 건너뛰기 차감은 3초, 첫 오답과 두 번째 오답의 입력 잠금은 각각 0.8초와 1.5초다.

같은 문제 순서에서 전략을 비교하려면 저장된 그림으로 실행하는 플레이테스트 빌드를 사용한다. 동일한 시드와 단계에서는 각 판의 제시어, 그림, 보기 순서가 재현된다. 기록은 일반 플레이와 별도로 저장된다.

```sh
flutter run --dart-define=QUIZ_PLAYTEST_SEED=42 --dart-define=QUIZ_PLAYTEST_LEVEL=3
```

같은 시드에서 빠른 추측, 결정적인 획을 기다리는 플레이, 모르겠으면 건너뛰는 플레이를 비교한다. 여러 시드와 서로 다른 숙련도의 플레이어를 사용해 점수, 라운드 길이, 첫 선택 시점, 건너뛰기 횟수를 기록한다. 일반 빌드에서는 1~5단계의 정답률과 첫 선택 시간, 난이도 완화 직후 정답률을 비교한다.

#### 밸런스 검수 목표

밸런스 디자인 목표는 95점 이상이다. 아래 항목을 검증한 뒤 조정 여부를 결정한다.

| 검수 항목 | 조정 기준 |
|---|---|
| 플레이 전략 비교 | 동일한 시드와 단계에서 빠른 추측, 획을 기다린 뒤 선택, 건너뛰기 위주의 플레이를 비교한다. 빠른 추측만으로 여러 시드에서 좋은 점수가 반복되면 오답 잠금을, 무조건 기다리는 편이 유리하면 보상과 펜 속도를 검토한다. |
| 건너뛰기와 보너스의 비용 | 초보자가 건너뛴 뒤 라운드가 자주 바로 끝나는지, 숙련자가 시간 보너스 상한에 너무 일찍 도달하는지 본다. 첫 시도와 반복 플레이의 결과를 나눠 비교한 뒤 차감·보너스·상한 중 원인에 해당하는 값만 조정한다. |
| AI 그림과 저장된 그림의 기록 비교 | 같은 제시어와 단계에서 정답률과 풀이 시간을 비교한다. 차이가 반복되는 조합은 먼저 그림과 보기를 검수하고, 수정 후에도 차이가 유지되면 출제 비율이나 최고 기록 비교 기준을 검토한다. |

빠른 추측과 기다리기의 구분은 실제로 선택할 때까지 진행된 획과 플레이어의 설명을 함께 본다. 자동으로 집계된 기록과 관찰 결과를 대조하고, 실기기와 첫 사용자 플레이테스트 결과가 쌓인 뒤 다시 평가한다.

제시어 345개는 [레벨 검수표](docs/quiz-level-review.csv)에서 검토한다. 자동 계산한 초반·완성 윤곽 여유는 같은 제시어의 윤곽과 가장 가까운 다른 제시어 간 유사도의 차이이며, 양수가 클수록 윤곽으로 구분하기 쉽다는 가설이다. 각 제시어의 친숙도, 헷갈리는 보기와 구분할 획, 여러 번 생성한 AI 그림의 식별성은 사람이 기록한다.

## 첫 버전과 로컬 AI

### 첫 버전 문제 구성

첫 제품 버전은 SketchFlow가 학습한 Quick, Draw! 카테고리 345개 전체를 출제 대상으로 삼는다. 각 카테고리에 한국어 정답, 오답 보기 세 개, 제시어 벡터를 연결한다. 아래 12개는 보기와 획을 설계하는 예시다. 보기 순서는 문제마다 섞고, 획 순서와 결정적인 획은 난이도에 맞는 생성 결과를 고르는 기준으로 삼는다.

| 정답 | 오답 보기 3개 | 획 순서 | 결정적인 획 |
|---|---|---|---|
| 우산 | 버섯, 낚싯바늘, 지팡이 | 손잡이 → 반원 → 지붕 가장자리 → 우산살 | 지붕 가장자리와 우산살 |
| 문어 | 오징어, 해파리, 거미 | 둥근 머리 → 눈 → 굽은 다리 → 빨판 | 굽은 다리 안쪽의 빨판 |
| 자전거 | 오토바이, 유모차, 킥보드 | 안장 → 삼각 차체 → 바퀴 → 페달 | 차체 가운데의 페달 |
| 고양이 | 토끼, 개, 여우 | 얼굴 윤곽 → 삼각 귀 → 코 → 양쪽 수염 | 짧은 주둥이 양옆의 수염 |
| 칫솔 | 빗, 붓, 포크 | 손잡이 → 좁은 목 → 작은 머리 → 칫솔모 | 작은 머리에 모인 짧은 칫솔모 |
| 열기구 | 해파리, 풍선, 낙하산 | 둥근 풍선 → 세로 봉제선 → 줄 → 바구니 | 줄 아래에 매달린 바구니 |
| 펭귄 | 오리, 백조, 부엉이 | 타원 몸통 → 부리 → 날개 → 흰 배 무늬 | 몸통에 붙은 짧은 날개와 배 무늬 |
| 아이스크림 | 컵케이크, 횃불, 당근 | 원뿔 → 둥근 한 스쿱 → 와플 무늬 | 원뿔 위의 둥근 스쿱 |
| 달팽이 | 소라, 애벌레, 롤케이크 | 소용돌이 껍데기 → 바닥에 붙은 몸통 → 더듬이 | 머리 위의 더듬이 두 개 |
| 소방차 | 버스, 구급차, 트럭 | 차체 → 바퀴 → 운전석 → 지붕 사다리 | 지붕 위에 놓인 사다리 |
| 모래시계 | 와인잔, 꽃병, 트로피 | 위아래 받침 → 가운데가 좁은 유리 윤곽 → 모래 | 좁은 목을 통과해 아래에 쌓이는 모래 |
| 선풍기 | 풍차, 꽃, 프로펠러 | 받침 → 기둥 → 원형 망 → 날개 | 기둥 위 원형 망 안의 날개 |

### 구현 범위

- **첫 제품 버전.** iOS와 Android에서 한국어 제시어 345개, 60초 모드, 4지선다, 5단계 난이도와 점수별 진행, 최고 기록, 오답 및 건너뛰기 복기를 제공한다.
- **기기 내 생성.** 345개 제시어의 벡터를 미리 담고, 공통 SketchFlow 생성 모델은 최초 한 번 내려받는다. 이후 인터넷 연결 없이 각 제시어의 새 획을 만든다. 첫 문제는 타이머가 시작되기 전에 준비하고, 이후 문제는 플레이 중에 미리 생성한다. [SketchFlow 모델 카드](https://github.com/doudin404/SketchFlow/blob/main/MODEL_CARD.md)
- **출시 전 검증.** 갤럭시 S24와 지원할 아이폰에서 모델 다운로드 용량, 메모리 사용량, 그림 생성 시간, 완성 그림 정답률을 확인한다. 새 문제가 준비되는 속도와 생성된 획의 난이도 분류가 실제 60초 라운드에서 안정적으로 작동하는지 검증한다.

## 플레이테스트 기준

- **오답 후 재선택을 알아차리는가.** 처음 플레이하는 사람에게 오답 안내를 미리 설명하지 않는다. 첫 오답 뒤 다시 누를 수 있는 보기를 스스로 찾는지, 잠긴 보기를 반복해서 누르거나 건너뛰기로 빠지는지 관찰한다.
  - 2026-11-25 확인. 안내를 보기 아래에 두고 재선택 가능한 보기를 강조한 버전에서 한 참여자가 첫 오답 뒤 멈추거나 다른 버튼을 눌렀다. 안내를 보기 위로 옮기고 건너뛰기 강조를 줄인 뒤, 같은 참여자가 다른 보기를 더 쉽게 눌렀다. 수정본을 처음 보는 참여자의 반응은 아직 확인하지 않았다.
- **몇 번째 획에서 맞히는가.** 입문 문제는 초반에, 도전 문제는 후반에 정답이 나오는지 확인한다.
- **찍기가 유리한가.** 획을 기다리는 플레이보다 보기를 빠르게 찍는 플레이가 높은 점수를 얻으면 오답 대기 시간을 조정한다. 오답별 입력 잠금과 그림 완성 후 2초 건너뛰기 대기 시간을 플레이테스트에서 확인한다.
- **왜 건너뛰는가.** 그림이나 보기의 모호함, 펜의 속도, 제시어의 친숙함을 살핀다.
- **60초가 끝나면 한 판 더 하는가.** 정답 직후 다음 그림으로 넘어가는 속도와 후반 난이도가 재도전을 끌어내는지 본다.
- **한 획 더 기다리는 게 재밌는가.** 같은 문제 팩으로 플레이하면서 답을 누르기 직전의 획, 오답 입력, 건너뛰기를 기록한다. 보기부터 연달아 누르는 편이 유리하면 오답 잠금을, 그림을 기다리는 시간이 길게 느껴지면 펜 속도를 조정한다.
